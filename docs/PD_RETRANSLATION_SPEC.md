# Mini-spec — Public-Domain Re-translation (make Tier C + PD authors publishable)

**Status:** Planned (dataset expansion) · **Date:** 2026-06-29 · **Not part of the v0.1.1 release.**

## Objective
Make the currently-unpublishable corpus **redistributable** by **re-translating public-domain source works with our own AI pipeline** (translate + judge QA), exactly as already done for Spurgeon (1,542 Tier B records). Because the **source is public domain** and the translation is **AI-generated by us** (not copied from a third party), the result infringes no one's copyright and can be released — but see "Authorship & Publication Disclosure" below: we do **not** claim human/scholarly authorship over the translation itself, only that we generated it.

## Why this is needed
The current Tier C (confessions) and part of Tier B (monergismo) are **not** redistributable — not because the *originals* are protected, but because we used **third-party modern Portuguese translations** (monergismo.com / IPB / CPRC / Ligonier / Cultura Cristã), which carry their own translation copyright. See `docs/` copyright audit. Spurgeon is already clean precisely because **we AI-translated the PD English ourselves** (`data/sources/spurgeon/*_avaliacao.json` = our translation-quality judge, score ≥ 95).

## ⛔ The one rule that must not break
**Translate from the PUBLIC-DOMAIN ORIGINAL — never from our existing copyrighted PT files.**
Re-translating/paraphrasing a protected PT translation still produces a **derivative of that protected translation** (the expression carries over). The translator's input MUST be the PD original-language text (or a confirmed-PD English translation). Discard the current `data/sources/confessions/*.pdf|*.txt` as a *source* (keep only for reference/diffing, not as translation input).

## Method (reuse the Spurgeon pipeline)
1. **Source PD originals** from authoritative public-domain archives (record the exact source + confirm PD status per item).
2. **AI-translate** EN/LA/DE → pt-BR (same translator step used for Spurgeon).
3. **Judge QA** (translation rubric: fidelity, fluency, terminology, style, completeness; keep the ≥ 95 threshold used for Spurgeon).
4. **Pastoral review for the confessions** (Tier A discipline) — a mistranslation in a confession is a *doctrinal* error; require human confessional review before inclusion.
5. **Rebuild** `tier_c.jsonl` (from the new translations) and a `tier_b_pd.jsonl` (PD authors), regenerate manifests, re-merge.

## Licensing & provenance
- Release under a **permissive license / CC0** ("to the extent rights subsist"), because **AI-generated translation copyrightability is contested** — we do not need to *hold* copyright to publish; we need to not infringe (satisfied: PD source + our translation) and to not misrepresent authorship (see below).
- **Transparency note in the dataset card:** "translations are AI-generated from public-domain originals, QA'd by an LLM judge (≥95) and (for confessions) pastoral review."
- **Confirm the translation model's terms of use** grant output rights to the user (our OpenRouter/DeepSeek path does; record the model + date).

## Authorship & Publication Disclosure (publish-critical)

**We are not the author or translator of this text — a machine is, and we say so.** This is the second half of "no copyright problems": it is not enough that the *source* is public domain — we must not accidentally *claim* human/scholarly authorship over an AI output, or overstate what the data is. Practical rules, enforced end to end:

1. **Call it what it is: synthetic data.** The pt-BR text in `tier_c_pd_translations.jsonl` (and any downstream `tier_c.jsonl`/`tier_b_pd.jsonl` built from it) is a **machine (LLM) translation**, not a human one, quality-scored by **machine judges**, not human reviewers (pastoral review, where it happens, is a separate, later, human step — see `scripts/10_retranslate_pd.py`'s pastoral-review gate). "AI-translated" and "synthetic data" are the accurate labels; never "translated by our team" or similar phrasing that implies human translation work.
2. **Per-record provenance, not just a manifest pointer.** Every translated unit (`scripts/10_retranslate_pd.py::process()`) carries inline: `ai_translated: true`, `data_nature: "synthetic (AI-generated translation)"`, `authorship_disclaimer` (full text), `translator_model`, `judge_models`, and the **source**'s own `source_title` / `source_url` / `source_publisher` / `source_license` — copied from `configs/pd_sources.json` at generation time. This makes each record **self-describing**: even if a downstream user filters/exports rows out of context, the non-infringement + non-authorship story travels with the data, not just in a README that could get separated from it.
3. **No claim of copyright over the translation.** We generated it; we do not assert it as *our* protected creative work (AI-generated-translation copyrightability is legally unsettled — see Licensing above), and we release rights permissively (CC0-style) rather than claiming exclusivity.
4. **The dataset card must repeat this prominently** (not bury it) — a short banner near the top: *"This dataset's Portuguese confession/catechism text is AI-generated (machine-translated) from public-domain English/Latin originals; it is not a human or denominational translation, and OpenScriptura does not claim scholarly authorship over it — only that we produced the translation via an AI pipeline, quality-checked by AI judges."* Link to the source (`source_title`/`source_url`) for every included work.
5. **Do not conflate with Tier A / pastoral review.** Tier A (60 examples) and any post-hoc pastoral-reviewed corrections ARE human-authored/human-reviewed and should be labeled as such — the synthetic-data disclosure above applies specifically to the AI-translated confession text, not to genuinely human work elsewhere in the corpus. Keep the two clearly distinguished in the card.

## Risks & mitigations
| Risk | Mitigation |
|---|---|
| Translating from the copyrighted PT (derivative) | **Hard rule**: input = PD original only; log the source per item |
| Doctrinal error in an AI translation of a confession | Pastoral/confessional human review before inclusion |
| AI mistranslation / hallucination | Judge QA ≥95 + spot human checks |
| Wrong PD assumption (jurisdiction) | Confirm PD per item + jurisdiction (esp. A.W. Pink 1952) |
| Model-terms conflict | Confirm translator model grants output rights; record it |
